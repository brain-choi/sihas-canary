# WCM-300-W 로컬 통합

WCM-300-W의 콘센트 스위치 4개, 채널별 소비전력 센서 4개,
합산 소비전력 센서 1개, 공용 전압·전류·주파수 센서 각 1개를 추가합니다.
콘센트마다 버튼잠금, 과부하·대기전력 차단 기준값, 자동 OFF 타이머 설정도 제공합니다.
WCM-300-W 지원은 v2.2.0부터 제공됩니다.

## 확인한 장치와 주소

펌웨어 **03.08**, **CFG=04**인 실기에서 확인했습니다. 제조사 공식
레지스터 규격을 확보한 것은 아니며, 로컬 명령 응답·상태 재조회·사용자의
현장 동작 확인·앱의 전력 표시와 대조한 결과입니다.

| 콘센트 | 제어 주소 | 전력 주소 | 전력 주소 검증 상태 |
| --- | --- | --- | --- |
| 1 | 0 | 4 | 무부하와 앱 표시 1W에서 확인 |
| 2 | 1 | 5 | 무부하와 앱 표시 18W에서 확인, 순간값 15~19 |
| 3 | 2 | 6 | 앱 표시 19~20W와 후속 측정 8회에서 확인 |
| 4 | 3 | 7 | 앱 표시 23W와 시계열 측정에서 확인, 관측 범위 19~26W |

주소는 모두 0부터 시작합니다. 제어값은 `0=OFF`, `1=ON`입니다.
전력은 16비트 정수 W로 표시하며, 현재 네 채널의 전력 주소가 모두 검증됐습니다.
각 전력 센서의 `register_mapping` 속성이 `verified` 또는 `inferred`로
검증 상태를 구분합니다. 현재 네 채널은 모두 `verified`이며 고유 ID는 유지됩니다.

합계 센서는 주소 4~7을 더한 **계산값**입니다. 장치의 별도 합계 레지스터나
누적 사용량을 읽은 값이 아니며, 현재 `contains_inferred_channels=false`로 표시합니다.

**주소 60은 전압으로 확정했습니다.** 원시값을 10으로 나누어 V로 표시합니다.
실기 원시값 2186·2187과 앱의 218.6·218.7V를 대조했으며, HA에는 소수점
한 자리의 공용 전압 센서로 노출합니다.

**주소 62는 사용자 요청에 따라 주파수로 확정했습니다.** `r62 / 10`을 Hz로
표시합니다. 관측값 598~599는 59.8~59.9Hz에 대응합니다. 센서의
`mapping_basis=user_confirmed`로 채택 근거를 기록하며, 별도 주파수계와
교정한 값은 아닙니다.

**주소 61은 사용자 요청에 따라 mA 단위 전류로 확정했습니다.**
`1000mA = 1A`이므로 `r61 / 1000`을 A로 표시합니다. 예를 들어 원시값
6575는 6.575A입니다. HA에서는 소수점 세 자리로 표시하며
`mapping_basis=user_confirmed`로 채택 근거를 기록합니다.
사용자가 정격 1500W 주전자를 1번에 연결한 뒤, 명시적인 제어 요청에 따라
약 30초 켜고 원래 OFF로 복원했습니다. 가열 중 1번 전력은 1370~1390W,
전압은 219.1~219.5V, 원시 전류는 6504~6596이었습니다. mA로 해석하면
6.504~6.596A이며, 다른 부하를 포함한 `P/(V*I)`는 약 0.973~0.978입니다.
가열 전후 차이를 저항성 부하의 `P/V`와 비교하면 1A당 약 1004카운트여서
1000으로 나누는 배율을 강하게 지지합니다. 독립 전류계로 교정한 것은 아닙니다.
무부하 채널을 켠 상태에서도 원시값이 남았으므로 오프셋과 저전류 정확도,
합산 RMS 전류인지 채널별 전류 합인지는 별도 검증 대상입니다.
측정된 값에서 임의로 무부하 오프셋을 빼거나 보정하지 않습니다.

누적량의 하위 값 후보는 1번 주소 18, 2번 주소 20, 3번 주소 22, 4번 주소 24에서
앱의 Wh 값과 일치했습니다. 앱의 3번 0.003kWh·4번 0.002kWh 표시와
주소 22=3·24=2가 동시에 일치한 스냅샷도 확보했습니다. 주전자 실험 후
1번 주소 18=11과 앱 0.011kWh도 일치했습니다. 그러나 16/32비트 카운터 형식과 상위 워드 배치가
미확정이므로 누적 전력량 센서는 아직 생성하지 않습니다.

2026-11-25의 5분 기록(5초 간격, 61회)에서 총전력·총누적량과 직접 일치하는
별도 레지스터는 찾지 못했습니다. 16비트 정수, 인접 32비트 정수·float와
일반적인 배율을 비교한 결과이며, 다른 인코딩의 존재까지 배제한 것은 아닙니다.
3·4번만 부하가 있는 해당 구간에서 전력은 `r6+r7`, 누적량은 현재 작은 값의
범위에서 `r20+r22+r24`로 앱의 합계와 대응했습니다.

## 버튼잠금과 차단 설정

| 콘센트 | 버튼잠금 | 과부하 차단 | 대기전력 차단 | 주소 검증 |
| --- | --- | --- | --- | --- |
| 1 | 8번 비트 0 | 9번 하위 바이트 | 11번 | 사용자 승인 추정 주소 |
| 2 | 8번 비트 1 | 9번 상위 바이트 | 12번 | 앱 설정 및 원복과 대조 |
| 3 | 8번 비트 2 | 10번 하위 바이트 | 13번 | 사용자 승인 추정 주소 |
| 4 | 8번 비트 3 | 10번 상위 바이트 | 14번 | 앱 설정 및 원복과 대조 |

버튼잠금은 HA 설정 스위치로, 차단 기준은 [숫자 입력란](https://contributors.home-assistant.io/core/entities/number/)으로 제공합니다.
과부하는 정수 `0~5 kW`, 대기전력은 정수 `0~2000 W`이며 `0`은 사용 안 함입니다.
2·4번 설정에는 `register_mapping=verified`, 1·3번에는 `register_mapping=inferred`를 표시합니다.
2번의 4 kW·1234 W와 4번의 1 kW·7 W는 실제 레지스터 값과 일치했습니다.
두 차단 메뉴에서 60초 유지 조건이 표시됐습니다. 실제 차단 시간은 별도 실기 검증 항목입니다.

설정을 쓸 때는 먼저 현재 워드를 읽고, 버튼잠금의 해당 비트,
과부하의 해당 바이트 내 하위 3비트, 대기전력의 하위 11비트 중 대상 필드만 바꿉니다.
같은 워드의 다른 콘센트 값과 나머지 비트는 보존합니다. 실기의 2번 콘센트가 꺼진 상태에서
버튼잠금, 과부하 1 kW, 대기전력 7 W를 각각 로컬로 설정하고 복원했습니다.
여섯 번의 명령 모두 응답 에코와 재조회가 일치했고, 콘센트 전원 상태도 유지됐습니다.

## 자동 OFF 타이머

| 콘센트 | 레지스터 | 확인 근거 |
| --- | --- | --- |
| 1 | 26 | 앱의 123분 설정에서 사용 여부 On/Off 대조 및 로컬 시간 쓰기 |
| 2 | 27 | 사용자가 채택한 주소에서 로컬 시간과 사용 여부 쓰기 |
| 3 | 28 | 사용자가 채널별 배열을 채택 |
| 4 | 29 | 앱의 1234분 설정과 대조 |

최상위 비트 `0x8000`은 타이머 사용 여부입니다. 1번에서 사용 여부만 켜자
`0x007B`가 `0x807B`로 바뀌고 설정 시간은 123분으로 유지됐습니다.
HA는 채널마다 사용 여부 스위치와 정수 `1~1800분` 입력란을 제공합니다.
시간을 변경할 때 하위 11비트만 갱신하므로 사용 여부와 다른 비트가 보존됩니다.
사용 여부를 바꿀 때는 최상위 비트만 갱신합니다.
2·3번 타이머 엔티티는 `register_mapping=confirmed`, `mapping_basis=user_confirmed`로 표시합니다.

실기에서 로컬 쓰기로, 전원이 꺼진 1번은 사용 비트를 유지하면서
123분을 124분으로 변경했고, 2번은 사용 Off 상태에서 1분을 7분으로 변경한 뒤
사용 여부를 켜고 껐습니다. 여섯 번의 변경 및 원복 명령 모두 정확한 에코와 재조회가
일치했습니다. 두 타이머 설정은 실험 전 값으로 복원됐고 네 콘센트 전원 상태는 동일했습니다.

4번 콘센트 전원과 타이머가 모두 켜진 동안 3초 간격으로 3분간 61회 조회했습니다.
29번은 설정값 `0x84D2`를 유지했고 바뀐 주소는 6번 소비전력과 60~63번 계측값 및 시각이었습니다.
이 구간의 0~63번 레지스터에서는 남은 시간에 대응하는 값이 관측되지 않았습니다.

## 통신과 오류 처리

- SiHAS 형식의 로컬 UDP, 포트 502를 사용합니다.
- 기능 `0x03`으로 주소 0부터 64개 레지스터를 읽습니다.
- 137바이트 응답의 트랜잭션 ID, 프로토콜·길이·체크섬/유닛 필드,
  기능 코드, 데이터 길이를 검증합니다.
- 기능 `0x06`으로 콘센트 전원 주소 0~3과 설정 주소 8~14, 26~29를 씁니다.
  정확한 응답 에코와 새로운 상태 읽기가 모두 일치해야 제어를 성공으로 처리합니다.
- 32개 엔티티가 하나의 코디네이터를 공유하며 5초마다 한 번 조회합니다.
  제어 성공 시 새 스냅샷으로 스위치, 센서, 설정을 함께 갱신합니다.
- 통신 실패나 잘못된 응답은 엔티티를 사용 불가로 처리합니다. 다음 정상
  조회에서 자동 복구합니다. 상태를 임의로 OFF 또는 0W로 대체하지 않습니다.
- 쓰기와 재조회는 직렬화됩니다. 초기 설정, 재시작, 일반 폴링에서는 읽기만
  수행하며 콘센트를 자동으로 켜거나 끄지 않습니다.

## 설치와 장치 등록

기존 설정을 삭제하거나 SiHAS 통합을 제거할 필요 없이, 전체
`custom_components/sihas` 폴더를 WCM 지원 코드로 교체하고 HA를 재시작합니다.
여러 파일을 함께 변경하므로 `wcm.py` 하나만 복사해서는 동작하지 않습니다.
Marketplace/HACS로 유지하려면 WCM 지원이 포함된 이 포크의 릴리스를 사용합니다.

1. 시하스 앱에서 **로컬통신(ST/HA)**을 활성화합니다.
2. 공유기에서 장치의 IP를 예약합니다.
3. HA의 **설정 → 기기 및 서비스 → 통합 구성 요소 추가 → SiHAS**를 엽니다.
4. 자동 발견된 WCM을 선택하거나 다음 항목으로 수동 등록합니다.
   - 장치 종류: `WCM`
   - IP·MAC: 실제 장치의 값
   - CFG: 장치가 `CFG=04`로 보고한다면 정수 `4`
   - 이름: 원하는 장치 이름
5. 콘센트 스위치 4개, 전력 센서 5개, 전압·전류·주파수 센서 각 1개를 확인합니다.
   기기의 구성 항목에서 버튼잠금 4개, 차단 기준값 8개,
   자동 OFF 사용 여부 4개와 시간 4개를 조작할 수 있습니다.

기존 RCM의 도메인·기기 식별자·고유 ID는 변경하지 않습니다.
WCM의 MAC은 소문자 콜론 형식으로 정규화하며 다음 ID를 사용합니다.

- 기기 식별자: `("sihas", device_mac)`
- 스위치: `WCM-{device_mac}-outlet-1` ~ `outlet-4`
- 버튼잠금: `WCM-{device_mac}-button-lock-1` ~ `button-lock-4`
- 과부하 차단: `WCM-{device_mac}-overload-cutoff-1` ~ `overload-cutoff-4`
- 대기전력 차단: `WCM-{device_mac}-standby-cutoff-1` ~ `standby-cutoff-4`
- 자동 OFF 사용 여부: `WCM-{device_mac}-auto-off-timer-1` ~ `auto-off-timer-4`
- 자동 OFF 시간: `WCM-{device_mac}-auto-off-time-1` ~ `auto-off-time-4`
- 개별 전력: `WCM-{device_mac}-power-1` ~ `power-4`
- 합계 전력: `WCM-{device_mac}-power-total`
- 공용 전압: `WCM-{device_mac}-voltage`
- 전류: `WCM-{device_mac}-current`
- 주파수: `WCM-{device_mac}-frequency`

## 검증

```sh
python -m unittest discover -s tests -v
python -m compileall -q custom_components/sihas tests
```

오프라인 테스트는 실제 구현의 클라이언트·패킷 생성기·UDP 송신기·파서·
코디네이터·엔티티를 사용합니다. HA의 기본 인터페이스와 UDP 상대 장치는
대체하므로 실제 HA 스케줄러·플랫폼 실행을 검증한 테스트는 아닙니다.
실제 수신한 전력, 전압, 전류, 주파수, 2·4번 차단 설정 및 1·4번 타이머 패킷을
개인정보 없이 고정 데이터로 포함합니다. 설정 테스트는 채택한 주소, 입력 제한,
공유 워드의 동시 변경과 재조회 불일치, 타이머 시간과 사용 여부의 독립 변경을 확인합니다.

잘못된 응답·손실·재시도·읽기 복구, 적용되지 않은 쓰기의 탐지, 동시 명령,
엔티티 ID, 추정 주소 표시, 전압·전류·주파수 변환, DHCP 갱신, 시작·종료 시 정리를 확인합니다.
더 큰 부하의 배율과 누적 전력량의 전체 카운터 형식은
추가 검증 대상입니다.
